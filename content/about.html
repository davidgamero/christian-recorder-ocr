From scans to searchable history

This research archive makes a collection of The Christian Recorder, the newspaper of the African Methodist Episcopal Church, easier to search. It provides uncorrected machine transcriptions and direct links to the original documents.

The Online Books Page at the University of Pennsylvania is the source catalog used to identify these volumes. Scans and existing OCR derivatives come from Internet Archive. This project is independent of those institutions.

Collection and provenance

We downloaded 44 JP2 source bundles (about 2.11 GB), one connection at a time, rate-limited to 512 KiB/s with 15-second pauses, resumable transfers, checksum checks and server-backoff handling. The actual ZIPs contain 2,376 scans; one volume contains 51 images rather than the 52 advertised in catalog metadata.

The final GLM text contains about 21.1 million whitespace-separated word tokens, occupying 121.4 MB as UTF-8 text. These counts include repeated or incorrect output. All scans produced saved results; 435 scans have output quality flags. Completion is not an accuracy certification. A scan may include two printed pages, and scan numbers include separator cards.

What we tested

We first built a CPU Tesseract pipeline with a learned seven-column layout, curved gutter alignment, overlapping strips and source-coordinate mapping. We then compared DeepSeek Flash, GLM-OCR and PaddleOCR-VL-1.6 on identical saved images, as whole pages, full columns, short chunks and isolated reference crops.

Whole-page vision requests repeatedly produced unreliable or repetitive output. Short chunks preserved more small-print detail. GLM chunks had no truncations in the tiny pilot; Paddle had one. On four isolated crops (395 words), character error was 0.37% for DeepSeek, 0.58% for Paddle, 1.11% for GLM and 4.20% for Linux Tesseract.

These references were provisional and previously inspected. Page-mode scores used reference-assisted excerpt matching, not full-page recall. Linux fixed chunks differ from the original overlapping-strip Tesseract pipeline. Historical DeepSeek calls used two concurrent requests, while initial local comparisons were sequential. These are not corpus-wide accuracy measurements.

Why the full run needed another layout iteration

An early run mistakenly treated landscape book spreads as separator cards. It cut wide horizontal strips across multiple columns, causing severe repetition. That run was stopped after 292 scans. The published run uses preparation version 4: separate leaf detection, printed-rule gutter proposals, sloped masthead cutoffs, bounded source-resolution chunks and explicit source polygons. Difficult advertisements, curved gutters, unusual column counts and missed text still require review.

Decode CUDA graphs reduced CPU launch overhead and raised sampled GPU utilization from about 30% to about 95%. All 264 benchmark requests completed without errors or truncation; the checked excerpt scores stayed unchanged, though some outputs differed slightly. Production later added bounded next-page preparation and a shared cross-page request queue. The completed run therefore contains both earlier eager and later graph-accelerated sessions.

Original text and lexical review

Original searchable text is kept separate. The local 27-page PDF text layer was extracted with pdftotext; for the full JP2 archive we preserve Archive's page-mapped DjVu OCR derivative. That derivative is not claimed to be byte-identical to the corresponding PDF's text layer. Original OCR is loaded on demand on scan pages and excluded from the search index to prevent duplicate results.

A checksum-pinned wiki100k frequency list helped measure recognized words, misses, text volume and repeated sequences. A contextual AI review of 300 priority word types found many original-OCR corruptions, but also genuine names, period vocabulary and advertising notation such as doctress, 12mo, 2d and tf. Dictionary hits can still be wrong in context: “may friend” may mean “my friend.” A dictionary score is not transcription accuracy.

How to use this archive

Use search to locate promising passages, then inspect the original scan before citing. Names, spelling and punctuation may be altered; passages may be omitted, repeated or invented. Date labels are derived from Archive identifiers or metadata and can be incomplete. The explicit source member name and checksum accompany every scan.

The site uses static HTML and Pagefind. Search runs in your browser and downloads index fragments on demand. No account, API key, analytics service or inference server is needed. Original images are not bundled or automatically fetched by this site.

For build instructions, exact model revision and research details, see the repository README. To report a transcription problem, open an issue with the scan ID and source location. This site preserves offensive or outdated historical wording without endorsing it.
